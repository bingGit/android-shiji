# VoiceFlow V3 Implementation WWAS

日期：2026-07-05

## Source Of Truth

- 原型文件：[docs/prototype/voiceflow-v1.pen](prototype/voiceflow-v1.pen)
- 重点参考分区：
  - `实时转写 V3：极简背景化`
  - `V3 其他页面延展：简洁背景化风格`
- 设计取向：以 V3 为准，追求简洁、背景化、低卡片感。动态状态可以按真实业务实现，但最终体感应与 V3 原型一致。

## Implementation Guardrails

- 记录页可以最大程度背景化，实时转写直接成为页面内容。
- 卡片列表、详情、设置页不能完全无边界，需要保留轻分隔、明确点击区和高风险操作提示。
- 原文是主资产；AI 处理结果不能覆盖原文。
- 每完成一个页面，使用 `pm-ai-shipping:intended-vs-implemented` 对照原型检查偏差。
- 全部页面完成后，使用 `pm-execution:test-scenarios` 补完整测试清单。

## WWA Backlog

### 1. Establish V3 Design Tokens And Shared Components

**Why:** V3 风格依赖克制的一致性。先沉淀颜色、字号、间距、轻分隔、底部导航和操作 chip，能避免各页面各自实现导致风格漂移。

**What:** 在 Compose 中建立 V3 视觉基础，包括背景色、主/次文字、状态色、轻分隔线、底部导航、图标按钮、操作 chip、设置行等共享组件。实现以 Pencil V3 原型为参考，不做逐像素复刻。

**Acceptance Criteria:**
- 记录、卡片、详情、设置页面使用统一 token 和共享组件。
- 底部导航与 V3 原型一致：三 tab、轻玻璃感、当前 tab 低对比高亮。
- 操作按钮以 icon + 短文字 chip 为主，避免重卡片和大按钮堆叠。
- 文本层级在小屏上不重叠、不截断。

### 2. Implement V3 Record Page With Background-Based Real-Time Transcription

**Why:** 记录页是产品核心体验。用户需要在说话时确认内容正在被实时识别，同时界面保持简洁，不被弹框或卡片打断。

**What:** 按 `实时转写 V3：极简背景化` 实现记录页状态：空闲、按住/录音中、实时转写增长、松开后极简草稿区。实时转写内容融入背景，只用状态点、文字层级、当前句轻高亮和声场反馈表达状态。

**Acceptance Criteria:**
- 空闲态能清楚引导用户开始记录。
- 录音中展示实时转写，已确认文本弱化，当前句轻高亮。
- 长内容状态能保留最新一句位置，不让页面布局跳动。
- 松开后转成可编辑草稿区，并展示编辑、润色、更多等必要操作。
- 录音中和保存中不会重复触发冲突操作。

### 3. Implement V3 Card List Page

**Why:** 卡片页需要从“消息流”变成“灵感笔记库”。用户要能快速扫描、进入详情、管理历史记录。

**What:** 按 `V3 卡片列表页` 实现轻分隔列表。列表项展示时间、标题、摘要、处理状态点和更多入口。保持弱卡片感，用线条和文字层级组织信息。

**Acceptance Criteria:**
- 用户能区分每条笔记，不会像连续消息流。
- 点击列表项进入对应详情页。
- 更多入口提供复制原文、删除等低频操作。
- 删除必须二次确认。
- 空状态引导用户回到记录页开始第一条记录。

### 4. Implement V3 Card Detail Workspace

**Why:** 详情页是一条灵感的工作空间。用户需要修正转写、执行简单 AI 处理，并管理处理结果。

**What:** 按 `V3 卡片详情页` 实现原文区、贴近正文的操作区、处理结果区。原文可编辑，润色/提炼等操作生成独立结果，不覆盖原文。

**Acceptance Criteria:**
- 原文可编辑、保存、复制。
- 润色、提炼入口清楚，生成中有交互状态。
- AI 结果作为独立版本展示，可复制、编辑、删除。
- 删除处理版本或整条笔记都需要二次确认。
- 失败状态保留原文和已有结果，并提供重试入口。

### 5. Implement V3 Settings Page

**Why:** 设置页需要降低配置焦虑。用户应清楚知道 API、模型、存储和权限是否可用，而不是面对技术参数堆叠。

**What:** 按 `V3 设置页` 实现低对比分组：API 认证状态、模型配置、后处理偏好、本地存储、权限与隐私、关于。设置页保留比记录页更明确的信息边界。

**Acceptance Criteria:**
- API 认证状态可见，能区分已认证、未配置、配置错误。
- 模型和中转站配置能被查看和编辑。
- 后处理偏好能展示润色/提炼等默认能力。
- 权限与隐私入口清楚。
- 设置项点击区域足够明确，不因极简风格牺牲可用性。

### 6. Persist Notes And Processing Results

**Why:** 用户已经反馈杀掉 App 后记录丢失。没有持久化，记录工具的核心价值不成立。

**What:** 为灵感笔记、原文草稿、处理版本、更新时间和状态实现本地持久化。页面刷新、App 重启后仍能恢复记录。

**Acceptance Criteria:**
- 记录完成后生成一条持久化笔记。
- App 重启后卡片列表仍显示历史记录。
- 原文编辑和 AI 结果修改能持久化。
- 删除笔记和处理版本后重启仍保持删除结果。

### 7. Stabilize AI Post-Processing States

**Why:** 润色、提炼等后处理是辅助能力，但如果无状态或失败信息不清，会破坏用户对记录资产的信任。

**What:** 梳理后处理请求：认证状态、生成中、成功、失败、重试。结果必须附着在当前笔记上，并可管理。

**Acceptance Criteria:**
- 点击润色/提炼后按钮进入生成中状态。
- 生成中避免重复提交和互相覆盖。
- 成功后新增独立处理版本。
- HTTP 错误、配置缺失、模型失败都有可理解提示。
- 失败不会丢失原文和已有处理版本。

### 8. Page-Level Intended Vs Implemented Reviews

**Why:** 原型已经明确了目标体感，开发过程中最容易出现“功能有了但体感偏了”。逐页审查能及时纠偏。

**What:** 每完成一个页面后，用 `pm-ai-shipping:intended-vs-implemented` 审查 V3 原型意图与代码实现的差距。审查对象至少包括记录页、卡片列表、卡片详情、设置页。

**Acceptance Criteria:**
- 每个页面都有一次对照原型的偏差检查记录。
- 每个偏差包含预期、实现证据、影响和修复建议。
- 高影响偏差在进入下一页前处理或明确延期。
- 不把“能用”当成“符合原型体验”。

### 9. Final Test Scenario Pack

**Why:** V3 落地不仅是静态 UI，还包含录音、实时转写、保存、编辑、删除、后处理和错误恢复。测试清单能保证主链路闭环。

**What:** 开发完成后，用 `pm-execution:test-scenarios` 输出测试场景，覆盖正常路径、边界情况和错误处理。

**Acceptance Criteria:**
- 覆盖记录页：空闲、录音中、实时转写、松开保存、继续记录。
- 覆盖卡片列表：历史显示、进入详情、删除确认、空状态。
- 覆盖详情页：编辑原文、润色/提炼、复制、删除处理版本。
- 覆盖设置页：认证状态、配置错误、权限入口。
- 覆盖重启恢复、网络失败、HTTP 404/401、无转写结果等异常。
