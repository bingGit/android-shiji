# Android VoiceFlow：创作者快速灵感捕捉与二次创作 PRD

**日期**：2026-07-02  
**产品阶段**：Existing product / MVP 需求优化  
**目标用户**：创作者  
**核心方向**：桌面快捷入口 + 快速语音记录 + 灵感卡片 + 先记后处理

---

## 1. 背景与问题

Android VoiceFlow 当前定位是一个 Android 实时语音转文字工具：用户开始录音后实时看到转写结果，停止后生成最终文本，并支持总结、润色、改写等后处理能力。

在重新讨论需求后，当前最重要的目标不应只是“实时语音转文字”，而是服务创作者的一个高频痛点：

> 灵感出现得很快，消失得也很快。创作者需要一个可以瞬间打开、快速记录，并在之后继续润色整理的语音入口。

因此，产品优先级需要从“完整语音转写工具”进一步收敛为：

> 一个可以从 Android 桌面快速打开的创作者灵感捕捉工具。用户先用语音抓住原始想法，再在事后进行润色、总结、改写和成稿。

---

## 2. 产品目标

### 2.1 核心目标

让创作者可以在灵感出现时，用最低操作成本完成：

1. 快速打开记录入口；
2. 快速开始语音记录；
3. 实时获得文字转写；
4. 停止后自动保存为灵感卡片；
5. 之后对原始转写做润色、总结、改写等二次处理；
6. 复制原文或处理结果到其它创作工具。

### 2.2 体验原则

| 原则 | 说明 |
|---|---|
| 速度优先 | 记录入口必须尽量短，不能让模板选择、设置项、历史列表阻碍记录。 |
| 先记后处理 | 灵感捕捉阶段不要求用户先选择输出形态，停止录音后再处理。 |
| 原文保留 | AI 后处理结果不能覆盖原始转写。 |
| 卡片沉淀 | 每次记录不是一条临时历史，而是一张可回看的灵感卡片。 |
| 低侵入 | 不做后台偷偷录音，不做用户无感上传。 |

## 3. 目标用户

### 3.1 优先用户

创作者，包括但不限于：

- 公众号作者；
- 小红书创作者；
- 短视频脚本创作者；
- 播客、课程、知识分享者；
- 经常用口述整理想法的人；
- 需要把碎片灵感沉淀成内容素材的人。

### 3.2 用户特征

- 灵感出现时间不固定；
- 很多想法一开始是口语化、碎片化的；
- 不希望在捕捉灵感前先做复杂选择；
- 事后愿意把原始内容润色、整理、扩写；
- 通常会把内容复制到微信、Obsidian、飞书、公众号后台、小红书或其它编辑器继续处理。

## 4. 核心场景

### 4.1 场景 A：突然想到一个观点

用户在路上突然想到一个观点：

> AI 工具真正改变的不是效率，而是表达门槛。

理想流程：

```text
点击桌面“快速记录”入口
→ App 进入快速记录模式
→ 用户直接口述
→ 实时转写
→ 停止录音
→ 自动保存为灵感卡片
→ 稍后点击“润色表达”或“整理成文”
```

### 4.2 场景 B：先乱说，再整理

用户并不确定这段内容最终要写成公众号、小红书还是短视频脚本，只想先把想法说出来。

理想流程：

```text
先记录原始口述
→ 保存原文
→ 事后选择：
  - 润色表达
  - 提炼要点
  - 改写成更完整段落
  - 复制到其它工具继续创作
```

### 4.3 场景 C：一天记录多个碎片

创作者一天可能记录多个灵感：

- 一个标题想法；
- 一个选题角度；
- 一个比喻；
- 一个故事素材；
- 一段文章开头；
- 一个待展开观点。

这些内容需要以灵感卡片的形式沉淀，而不是只作为临时剪贴板文本存在。

## 5. MVP 范围

### 5.1 MVP 一句话

> 用户可以通过桌面快捷入口快速打开 Android VoiceFlow，立即语音记录灵感；停止后内容自动保存为灵感卡片，并可对原始转写进行润色、总结和改写。

### 5.2 P0 功能

| 功能 | 说明 |
|---|---|
| 桌面快速记录入口 | 用户可以从 Android 桌面进入快速记录流程。 |
| 快速记录模式 | 极简录音页面，突出录音状态、停止按钮、实时转写和音量反馈。 |
| 实时语音转写 | 说话过程中实时显示 partial transcript，停止后生成 final transcript。 |
| 自动保存灵感卡片 | 停止并生成最终转写后，自动保存为一张灵感卡片。 |
| 原始转写保留 | 原文永久保留，后处理结果不能覆盖原文。 |
| 二次处理 | 对原始转写执行润色、总结、改写。 |
| 复制能力 | 支持复制原始转写和任意后处理结果。 |
| 最近灵感列表 | 至少展示最近若干张灵感卡片，便于找回。 |

### 5.3 P1 功能

| 功能 | 说明 |
|---|---|
| 自动标题 | 优先用规则生成标题，后续可接模型生成。 |
| 灵感卡片详情页 | 展示原文、处理结果、时间、录音时长等信息。 |
| 卡片状态 | 标记未处理、已润色、已总结、已改写。 |
| 继续补充 | 在同一张卡片中追加新的语音片段。 |
| 快捷入口引导 | 首次使用时引导用户添加桌面快捷方式。 |

### 5.4 P2 功能

| 功能 | 说明 |
|---|---|
| 模板化后处理 | 小红书笔记、公众号开头、短视频口播稿、文章大纲等。 |
| 智能推荐下一步 | 根据原文判断推荐生成标题、扩写、大纲等动作。 |
| 标签与分类 | 支持选题、观点、故事、金句等类型。 |
| 搜索灵感卡片 | 按关键词搜索历史灵感。 |
| 收藏 / 置顶 | 标记重要灵感。 |

## 6. 用户流程

### 6.1 首次使用流程

```text
打开 App
→ 展示产品定位：一键记录灵感，稍后整理成内容
→ 请求麦克风权限
→ 引导配置 Provider / API Key
→ 引导添加桌面快速记录入口
→ 进入首页
```

说明：

- 首次使用需要完成权限和 Provider 配置，无法做到真正一键记录；
- 完成首次配置后，日常记录应尽量接近一键启动；
- 如果用户暂时不添加桌面入口，仍可从 App 首页开始快速记录。

### 6.2 日常快速记录流程

```text
点击桌面“快速记录”入口
→ 启动 App 并进入快速记录模式
→ 如果权限和配置完整，直接准备录音
→ 用户开始口述
→ 实时显示转写内容
→ 用户点击停止
→ 等待 final transcript
→ 自动保存为灵感卡片
→ 显示原文和二次处理入口
```

### 6.3 二次处理流程

```text
打开灵感卡片
→ 查看原始转写
→ 点击“润色表达”
→ 生成润色版本
→ 用户复制润色版本
```

同一张卡片可继续执行：

```text
点击“提炼要点”
→ 生成总结版本

点击“整理改写”
→ 生成改写版本
```

## 7. 快速入口设计

### 7.1 MVP 推荐实现：Launcher Shortcut

MVP 优先实现 Android Launcher Shortcut，而不是完整 Widget。

入口示例：

```text
Android VoiceFlow
- 打开应用
- 快速记录
```

点击“快速记录”后：

```text
启动 MainActivity
→ 带入 action = quick_record
→ App 进入快速记录模式
```

### 7.2 后续增强：桌面 Widget

后续可以增加 1x1 Widget：

```text
[🎙 快速记录]
```

点击 Widget 后进入同样的快速记录模式。

Widget 的优先级低于 Launcher Shortcut，因为 Widget 需要额外处理尺寸、刷新、样式和兼容性，而 MVP 当前最重要的是验证快速记录流程。

### 7.3 入口体验目标

| 指标 | 目标 |
|---|---|
| 已授权情况下进入记录页 | 尽量在 1 秒内完成 |
| 日常开始记录点击数 | 1-2 次 |
| 首次权限阻塞 | 只在首次使用出现 |
| 入口文案 | 快速记录 / 记录灵感 |

## 8. 快速记录模式设计

### 8.1 页面目标

快速记录页面只服务一个目标：

> 让用户尽快把想法说出来。

### 8.2 页面元素

P0 页面元素：

- 录音状态；
- 大号开始 / 停止按钮；
- 实时转写文本区域；
- 音量波形或音量条；
- 录音时长；
- 取消按钮；
- 网络 / Provider 状态提示。

### 8.3 不应出现的元素

快速记录阶段不展示：

- 模板选择；
- 风格选择；
- 历史列表；
- 多个后处理按钮；
- 复杂设置项；
- 过多说明文字。

这些内容可以放到录音结束之后或设置页面。

## 9. 灵感卡片设计

### 9.1 卡片定义

每次成功生成 final transcript 后，系统创建一张灵感卡片。

### 9.2 数据模型

建议字段：

```text
IdeaCard
- id
- title
- originalTranscript
- createdAt
- updatedAt
- durationMs
- source = voice
- status
- processingResults[]
- tags[]
- isFavorite
- modelInfo
```

后处理结果：

```text
ProcessingResult
- id
- type: polish | summarize | rewrite | custom
- title
- content
- createdAt
- model
- promptVersion
```

### 9.3 标题生成规则

MVP 可以先用规则生成标题：

1. 如果第一句话长度适中，使用第一句话；
2. 否则取原文前 20-30 个字；
3. 如果内容为空，显示“未命名灵感”；
4. P1/P2 再使用模型生成更准确标题。

### 9.4 卡片状态

```text
未处理
已润色
已总结
已改写
已复制
```

状态可以根据处理结果自动推导，不一定需要用户手动维护。

## 10. 二次处理设计

### 10.1 P0 后处理动作

当前保留三类核心动作，但文案更贴近创作者：

| 操作 | 原能力 | 输出目标 |
|---|---|---|
| 润色表达 | polish | 保留原意，改善表达，让文本更顺畅。 |
| 提炼要点 | summarize | 提取核心观点和要点。 |
| 整理改写 | rewrite | 把口语化内容整理成更成文的表达。 |

### 10.2 后处理原则

- 必须由用户主动点击触发；
- 处理结果显示在独立区域；
- 不覆盖原始转写；
- 每次处理结果都可以复制；
- 失败时保留原文和其它已有处理结果；
- 可以对同一张卡片多次处理。

### 10.3 P2 模板扩展

后续可扩展为：

```text
把这条灵感变成：
- 小红书笔记
- 公众号开头
- 短视频口播稿
- 文章大纲
- 选题卡
- 金句列表
```

这些模板应放在记录之后，而不是记录之前。

## 11. 验收标准

### 11.1 快速入口

- 用户可以从 Android 桌面快捷入口进入快速记录模式；
- 快捷入口与普通打开 App 的行为可区分；
- 权限和 Provider 配置已完成时，进入后可以快速开始录音；
- 权限缺失时显示明确引导；
- Provider 配置缺失时提示用户完成配置，不崩溃。

### 11.2 录音与转写

- 首次录音正确请求麦克风权限；
- 录音中显示状态、时长、音量反馈；
- 实时转写内容持续更新；
- 停止后生成 final transcript；
- final transcript 为空时不创建有效卡片，并提示用户；
- 网络或 Provider 失败时不丢失已显示文本。

### 11.3 灵感卡片

- final transcript 成功后自动创建灵感卡片；
- 卡片包含原始转写、创建时间、标题；
- 原始转写不会被后处理覆盖；
- 用户可以从最近灵感列表重新打开卡片；
- 用户可以复制原始转写。

### 11.4 二次处理

- 用户可以对卡片执行润色表达；
- 用户可以对卡片执行提炼要点；
- 用户可以对卡片执行整理改写；
- 每个处理结果独立保存；
- 用户可以复制任意处理结果；
- 后处理失败时保留原始转写和已有结果。

### 11.5 隐私与安全

- API Key 不出现在日志中；
- 原始转写默认只保存在本地；
- 用户点击录音后才上传音频；
- 用户点击后处理后才上传文本；
- 设置中说明音频和文本会发送到用户配置的 Provider。

## 12. 非目标

MVP 明确不做：

- 录音前模板选择；
- 完整写作编辑器；
- 自动发布到公众号、小红书、微信等平台；
- 云同步；
- 多端同步；
- 复杂素材库管理；
- Prompt 市场；
- 后台长时间录音；
- 锁屏录音；
- 声纹识别；
- 说话人分离；
- 离线本地模型。

## 13. 关键假设与验证实验

### 13.1 假设 1：创作者首要痛点是捕捉速度

**假设**：创作者更需要快速抓住灵感，而不是一开始就生成完美内容。

**验证方式**：

- 让用户连续使用 3 天；
- 记录从想到内容到开始录音的耗时；
- 统计是否因为入口麻烦放弃记录；
- 观察用户是否在碎片场景中使用桌面快捷入口。

**成功标准**：

- 用户每天主动记录 ≥ 3 次；
- 多数记录来自快速入口；
- 用户反馈“比打开备忘录/微信输入更快”。

### 13.2 假设 2：先记后处理优于先选模板

**假设**：录音前选择模板会降低灵感捕捉效率。

**验证方式**：

对比两个原型：

```text
A：点击即录，停止后处理
B：先选模板，再开始录音
```

观察：

- 哪个流程开始记录更快；
- 用户主观上哪个压力更小；
- 用户是否因为模板选择犹豫。

**成功标准**：

- 大多数用户偏好 A；
- A 的开始记录耗时明显低于 B；
- 用户认为 A 更适合捕捉突然出现的想法。

### 13.3 假设 3：灵感卡片比普通历史更适合创作者

**假设**：创作者会回看、处理和复用历史灵感。

**验证方式**：

观察用户是否：

- 回看历史卡片；
- 对旧卡片进行润色/总结/改写；
- 复制旧卡片内容到其它工具；
- 希望继续补充同一条灵感。

**成功标准**：

- 至少 30% 的卡片在创建后被再次打开；
- 至少 20% 的卡片触发过后处理；
- 用户能说出“卡片”相比普通历史的价值。

### 13.4 假设 4：二次处理是核心价值而非附加功能

**假设**：用户记录后愿意使用润色、总结、改写来提升内容可用性。

**验证方式**：

统计：

- 每 10 次记录中触发后处理的次数；
- 哪个处理动作使用最多；
- 用户最终复制的是原文还是处理结果。

**成功标准**：

- 后处理触发率 ≥ 30%；
- 处理结果复制率高于原文复制率，或二者都有稳定使用；
- 用户认为处理结果节省了二次编辑时间。

## 15. 结论

Android VoiceFlow 的下一阶段需求应优先围绕“快速灵感捕捉”重构体验，而不是过早扩展成复杂 AI 写作平台。

当前最值得验证的产品判断是：

> 如果创作者可以从桌面一键进入记录，先把灵感说出来，再在灵感卡片中进行润色和整理，那么 Android VoiceFlow 就会从一个通用转写工具，变成一个更高频、更有创作价值的内容入口。
